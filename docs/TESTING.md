# Halo Soundbar 验证记录（2026-10-16）

范围：只适配 EDIFIER Halo Soundbar，USB VID `2D99` / PID `A063`，本次实机固件 `1.0.2`。

## 已发现并修复

- 音效选择的本地显示值被当作设备确认，后台也曾直接把请求值写入设备快照。现在保留真实回读，界面单独显示待确认值。
- 真机连续修改不同设置时，音效写入可能不生效。音量和音效现在回读确认，最多重试三次，失败保留真实状态。
- 亮度、速度、已应用颜色的连续修改可能互相覆盖。写入整条灯效记录时合并尚未回读的本地修改，但不包含待点击“应用此颜色”的草稿。
- 每 250 ms 发送滑条值仍可能快于设备约 900 ms 的灯效处理速度。后台合并连续的同类、同目标命令，保留最后值及重置等操作的顺序。
- 切换灯效前遗留的滑条操作可能写入另一个效果；切换页面又可能丢失最后一个滑条值。现在分别清理旧效果编辑、在导航前发送最终滑条值。
- 超时回退只随新快照执行，音量没有超时回退。现在每个界面 tick 都处理超时和断线清理。
- 断线时收到关机或恢复出厂命令会结束后台线程，导致永久停止重连。现在丢弃断线期间的设备命令，只在应用关闭时结束线程。
- 完整刷新未正确清除关灯后的旧记录，异常或截断灯效应答又可能被当成关灯。现在统一解析明确的 `[00]` 或完整灯效表，拒绝不完整应答。完整表中索引 8 的 B 字段也可报告开关状态。
- HID 读超时与取消同时完成时，可能丢弃已经收到的应答。现在保留取消过程中成功完成的报告。
- 设备查找原先允许其他漫步者型号回退匹配。现在仅连接 Halo Soundbar 的指定控制接口。
- 诊断工具默认读取还会运行包含写命令的普查。现在 `read` / `state` 只读，普查必须明确指定 `census`。

## 验证结果

- `cargo test --all-targets`：49 项通过；真机测试默认忽略，避免普通测试改变设备设置。
- `cargo clippy --all-targets -- -D warnings`：通过。依赖清单仍有现有 `lints.cargo` 提示，不影响构建。
- `cargo build --release --bin halo-soundbar --bin halo-diag`：通过。
- `cargo test --test hardware -- --ignored --nocapture`：通过。验证音量、三个音效模式、效果 3 的颜色/亮度/速度、关灯再开灯、连续十次灯效修改收敛及原设置恢复。
- Windows 界面实测：连接和固件显示、导航、选色不写设备、点击应用才写设备、应用后按钮禁用、恢复出厂对话框取消。
- 最后只读回查确认恢复本次开始时的音量 16、音乐模式 0、效果 1、颜色 `#43FF77`、亮度 100；完整灯效表与开始时一致。

后续界面验证：修复浅色主题下白色透明 PNG 不清晰的问题。使用同一测试窗口在运行时反复切换浅色/深色主题，确认音效和灯效图案同步变色，卡片布局及选中描边保持正常。正式版本继续跟随系统主题，不包含测试用自动切换逻辑。

主题设置验证：设置页提供跟随系统、浅色、深色三种选择，切换即时生效；重启应用验证深色偏好恢复成功，随后恢复默认跟随系统。新增偏好保存/替换、缺失/异常配置回退两项测试，自动测试合计 51 项通过，静态检查和正式构建通过。

## 复测

```powershell
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo run --bin halo-diag -- read
```

连接音箱、打开氛围灯并关闭其他控制客户端后，可主动运行真机测试。该测试临时改变普通设置，并回读确认恢复：

```powershell
cargo test --test hardware -- --ignored --nocapture
```
